# 前端界面清单（最小可交付）

本文档用于明确本项目在当前阶段前端需要实现的界面范围。目标是满足作业要求并支撑完整演示流程：登录 -> 开户 -> 下单 -> 撤单 -> 成交 -> 查询。

## 1. 页面总览

必须实现的页面建议如下：

1. 登录页面（JWT 认证）
2. 开户页面（客户开户录入）
3. 委托下单页面
4. 委托撤单页面
5. 委托成交录入页面（模拟成交）
6. 持仓查询页面
7. 委托记录查询页面
8. 成交记录查询页面

> 备注：以上 8 个页面覆盖当前业务流程，所有业务页面默认需登录后访问。

## 2. 页面详细要求

## 2.1 登录页面（JWT 认证）

- 页面目标：完成操作员登录，获取 JWT，并进入业务系统。
- 对应接口：`POST /api/auth/login`（若后端路径不同，以实际接口为准）
- 必填字段：
  - 用户名（或工号）
  - 密码
- 建议展示字段（登录成功后）：
  - 操作员名称
  - 当前登录状态
- 关键校验：
  - 必填校验
  - 密码最小长度校验
  - 登录失败提示（账号不存在、密码错误、账号禁用等）
- JWT 鉴权实现要求：
  - 登录成功后保存 `accessToken`（可选同时保存 `refreshToken`）。
  - 请求拦截器自动在 `Authorization` 请求头携带 `Bearer <token>`。
  - 路由守卫：未登录时访问业务页面自动跳转登录页。
  - 401 处理：清理 token，跳回登录页并提示“登录已失效”。
  - 退出登录：主动清理 token 和用户态缓存。

## 2.2 开户页面

- 页面目标：录入客户开户资料并提交到 `CustomerService`。
- 对应接口：
  - `POST /api/customer/open`
  - `GET /api/customer/{id}`（用于开户后回查展示）
  - `PUT /api/customer/{id}`（可选，支持资料修改）
- 必填字段：
  - 客户名称
  - 证件类别
  - 证件号码
  - 资产账户类别
- 建议展示字段（开户成功后）：
  - 客户ID
  - 资金账户ID
  - 证券账户ID（上海/深圳）
- 关键校验：
  - 必填校验
  - 证件号码格式校验（按证件类别可做差异化）
  - 同一证件号码重复开户提示

## 2.3 委托下单页面

- 页面目标：录入买入/卖出委托并提交到 `TradeService`。
- 对应接口：`POST /api/trade/order`
- 必填字段：
  - 客户ID
  - 资金账户ID
  - 股票代码
  - 委托价格
  - 委托数量
  - 买卖方向（买入/卖出）
- 建议展示字段（提交成功后）：
  - 委托ID
  - 委托状态
- 关键校验：
  - 买卖方向仅允许买入/卖出
  - 价格 > 0，数量 > 0
  - 数量按交易单位约束（可先按整数校验）
  - 页面侧基础校验 + 后端返回规则失败提示（如资金不足、可卖不足）

## 2.4 委托撤单页面

- 页面目标：提交撤单请求并展示撤单结果。
- 对应接口：`POST /api/trade/cancel`
- 必填字段：
  - 委托ID
  - 客户ID
- 建议展示字段（提交成功后）：
  - 撤单结果（成功/失败）
  - 当前委托状态
  - 退回资金或股份提示
- 关键校验：
  - 必填校验
  - 仅允许对可撤状态的委托发起撤单（前端可提示，最终以后端校验为准）

## 2.5 委托成交录入页面（模拟成交）

- 页面目标：模拟撮合成交，录入成交信息并提交。
- 对应接口：`POST /api/trade/execute`
- 必填字段：
  - 委托ID
  - 成交价格
  - 成交数量
- 建议展示字段（提交成功后）：
  - 成交ID（若返回）
  - 更新后的委托状态（部分成交/已成交）
- 关键校验：
  - 价格 > 0，数量 > 0
  - 成交数量不能超过委托剩余数量（以后端校验为准）

## 2.6 持仓查询页面

- 页面目标：按客户维度查询实时持仓。
- 对应接口：`GET /api/trade/position/{customerId}/{capitalAccountId}`
- 查询条件：
  - 客户ID
  - 资金账户ID
- 结果建议字段：
  - 股票代码
  - 持仓数量
  - 可用数量
  - 冻结数量
  - 成本价（若后端提供）

## 2.7 委托记录查询页面

- 页面目标：查询客户委托记录。
- 对应接口：`GET /api/trade/orders/{customerId}`
- 查询条件：
  - 客户ID（必填）
  - 资金账户ID（可选）
  - 证券账户ID（可选）
- 结果建议字段：
  - 委托ID
  - 股票代码
  - 买卖方向
  - 委托价格/数量
  - 已成交数量
  - 委托状态
  - 委托时间

## 2.8 成交记录查询页面

- 页面目标：查询客户成交记录。
- 对应接口：`GET /api/trade/trades/{customerId}`
- 查询条件：
  - 客户ID（必填）
  - 资金账户ID（可选）
  - 证券账户ID（可选）
- 结果建议字段：
  - 成交ID
  - 关联委托ID
  - 股票代码
  - 成交价格
  - 成交数量
  - 成交金额
  - 成交时间

## 3. 导航与交互建议

- 建议顶部导航或左侧菜单按业务流排序：
  - 登录 -> 开户 -> 下单 -> 撤单 -> 成交 -> 持仓查询 -> 委托查询 -> 成交查询
- 建议统一交互规范：
  - 表单提交按钮 loading 态
  - 成功/失败消息提示（toast）
  - 接口错误统一处理（网络错误、参数错误、业务规则错误）
  - 登录态显示（当前用户、退出登录入口）

## 4. 作业演示覆盖建议

为满足演示要求，建议前端准备以下可操作流程：

- 登录页面：完成 1 次有效登录与 1 次无效登录失败提示演示
- 开户页面：至少录入 3 个客户
- 下单页面：至少提交 3 笔委托
- 撤单页面：至少完成 1 笔撤单
- 成交页面：至少录入 5 笔成交
- 查询页面：可实时展示持仓、委托记录、成交记录变化
